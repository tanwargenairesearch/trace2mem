Connect your agents to your memory

Trace2Mem maintains one memory for each authenticated user. Your agents share that memory by using credentials belonging to you. No space or project ID is required.

Get started

  1. Sign in using your local bootstrap token or configured identity provider.
  2. Choose generation and embedding models in Models. Both roles need explicit model IDs. Local and cloud providers can be combined.
  3. Import a Protobuf JSONL trajectory, then request compilation.
  4. Refresh memory status. Once a revision is published, browse its index, search evidence, or ask a cited question.

Ask needs configured models and published memory. Source search and evidence reads do not require a generation call. Scripted providers are test fixtures, not real inference.

Two integration directions

Capture: submit events to /trace2mem.v1.IngestionService/AppendEvents. Use stable event IDs for retries. Events include session, source, actor, timestamp, and a typed message or tool payload. Durable acceptance does not mean compilation has finished.

Retrieve: connect a Streamable HTTP MCP client to /mcp using Authorization: Bearer YOUR_USER_TOKEN. Available tools: memory_index, memory_search, memory_read, memory_evidence, memory_context, and memory_status.

MCP alone does not capture conversations or inject initial context. Your integration must load memory_index when the conversation starts and separately submit trajectory events.

Credentials and isolation

Use a read token for retrieval, an ingest token for capture, and management credentials only for settings and token creation. Credentials determine the user; never add a user ID to event metadata expecting it to change ownership.

Portable access

The Go SDK, Connect JSON/gRPC API, CLI directory synchronization, and read-only Linux FUSE client expose the same published memory. Snapshots pin a revision. Downloaded files cannot be remotely recalled after forgetting.

Project status

This is an experimental agent memory service inspired by Brain. The per-user redesign is in progress. The LangChain reference adapter has passed local capture and retrieval checks. Automatic/daily scheduling and real-model memory-quality evaluation remain pending. See the repository implementation status before relying on these capabilities.
